# 麦麦减脂配餐助手


基于麦当劳 MCP 接口的减脂控卡配餐规划技能。根据用户设定的热量、蛋白质、钠、预算与忌口，在门店真实在售菜单中自动规划符合目标的餐品组合，输出逐项营养明细、整单营养合计与真实试算价格。全流程只读，不创建订单、不领取优惠券。

---

## 1. 项目简介

### 目标人群
需要控制每日热量、蛋白质与钠摄入的减脂期人群、健身增肌人群、慢性病饮食管理人群，以及在麦当劳就餐时希望快速做出"可控的一餐"决策的用户。

### 解决痛点
- 麦当劳官方 App 不提供按"热量 + 蛋白质 + 钠"多目标筛选的组合推荐，用户只能自行查营养成分表并心算。
- 营养表与菜单是两套独立数据，普通用户难以把两者对齐（尤其难以判断"套餐 vs 单品"、"规格差异"）。
- 减脂用户关心的往往是"这一顿还能吃什么"，而不是单个商品的热量；需要的是整单口径的核算结果。
- 门店菜单与商品编码会随时间变化，沿用历史数据容易算错价格或点到已下架商品。

本技能通过 MCP 只读接口串联"门店 - 菜单 - 营养 - 价格 - 优惠券"五类数据，在真实可售商品范围内完成营养达标与预算达标的联合求解，并给出可核验的接口级数据来源。

## 2. 核心能力清单

| 能力 | 说明 | 依赖接口 |
|---|---|---|
| 门店定位与选择 | 按城市 + 地标/地铁站关键词检索附近门店，返回距离、营业状态、门店编号 | `query-nearby-stores` |
| 门店真实菜单获取 | 拉取指定门店当前在售菜单与实时售价 | `query-meals` |
| 营养成分查询 | 获取全量餐品营养成分（能量、蛋白质、脂肪、碳水化合物、钠、钙） | `list-nutrition-foods` |
| 自动配餐求解 | 按热量上限、蛋白质目标、钠上限、预算上限、忌口五类约束自动组合 | 本地算法 + 上述数据 |
| 整单价格试算 | 对最终组合调用价格试算接口，输出原价、优惠、应付总价 | `calculate-price` |
| 优惠券可用查询 | 查询指定门店当前可用优惠券（可能为空） | `query-store-coupons` |
| 餐品详情查看（可选） | 查看套餐组成与特制选项 | `query-meal-detail` |
| 降级与异常处理 | 无解时输出最接近方案、差距说明与两个可落地的放宽建议 | 本地逻辑 |
| 迭代修改 | 支持更换单品、增减预算、调整忌口后重新配餐 | 本地逻辑 |

输出固定包含三项：【整单合计】【总价】【取餐建议】。

## 3. 运行前置条件

1. **运行环境**：支持 MCP（Model Context Protocol）的客户端，且已启用 mcd-mcp 服务。
2. **MCP Token**：需要在麦当劳开放平台完成 Token 申请，并在 MCP 配置中写入鉴权信息；Token 过期或无效时，全部接口调用将失败。
3. **网络连通**：需可正常访问麦当劳 MCP 服务端；离线状态下无法获取菜单与营养数据。
4. **必需输入**：用户需要提供取餐城市与位置关键词，以及目标营养指标（热量、蛋白质、钠）。预算与忌口为可选项。
5. **权限范围**：仅需只读权限，不需要下单、支付、积分等相关权限。

详细接入方式见 `MCP_INTEGRATION.md`，配置样例见 `mcp-config.example.json`。

## 4. 使用流程

1. **明确目标**：向技能提供今日剩余热量上限、蛋白质目标、钠上限；可选提供预算上限。若未完整提供，技能将给出推荐默认值并请求确认。
2. **提供位置与取餐方式**：提供城市 + 地标/地铁站名，并选择到店自取或得来速。
3. **选择门店**：技能返回附近门店列表（名称、地址、距离、营业状态、门店编号），用户选定其中一家。
4. **等待菜单拉取**：技能拉取该门店当前真实菜单（每次配餐前重新拉取）。
5. **回答忌口问题**：技能依据该店实际在售品类询问忌口（如不吃牛肉），按真实品类做过滤。
6. **获取配餐方案**：技能按约束组合餐品，逐项累加核实后，输出单品营养、整单合计、总价与取餐建议，并提示可用优惠券情况。
7. **迭代调整**：可提出更换单品、增减预算、调整忌口，技能重新配餐并重新试算价格。
8. **结束**：本技能到此为止，不提供下单环节。

## 5. 规则说明

### 5.1 只读声明
本技能仅调用只读接口（`query-nearby-stores`、`query-meals`、`list-nutrition-foods`、`calculate-price`、`query-store-coupons`、`query-meal-detail`）。明确禁止调用 `create-order`、`mall-create-order`、`draw-lottery`、`party-order-create` 等写操作。用户提出"下单 / 买 / 结算 / 领券"时，技能应拒绝并说明自身定位为规划工具。

### 5.2 规格剔除规则
菜单商品名必须能**唯一**对应营养表条目才能进入候选池。出现规格歧义时（例如菜单仅写"薯条"而未标明小/中/大杯、"麦乐鸡"未标明块数、"鲜萃咖啡"未标明杯型、"麦辣鸡翅"未标明块数，而营养表按不同规格分别列值），该商品一律剔除，并在输出中注明"XX 因规格不明未参与搭配"。禁止估算营养值，禁止猜测规格。若菜单中另有明确规格的条目（如"4块麦乐鸡"），该明确条目可正常参与。

### 5.3 编码不缓存规则
配餐一律以本次会话中当前这一次 `query-meals` 返回的商品编码与价格为准，禁止沿用历史查询、上一轮对话或缓存中的编码与价格。实测中发现同一门店不同时间返回的编码存在差异，因此每次配餐前必须重新拉取菜单。

### 5.4 无解时的降级方案
当门店、忌口与目标组合下不存在满足全部约束的方案时，按以下顺序处理：

1. 依次尝试降低蛋白质目标、放宽钠上限、放宽热量上限；如设置了预算，最后询问预算是否可小幅上浮。
2. 若仍无解，输出"最接近方案"，并明确标注未达标项及差距数值。
3. 同时给出两个放宽建议，每个建议须附完整的营养明细与真实试算价格，供用户直接对比选择。
4. 说明该门店/忌口/目标组合下无解的原因，并提供放宽目标、放宽忌口、更换门店三个方向。

### 5.5 价格换算规则
价格相关接口返回单位为"分"，展示时必须除以 100 转换为"元"。优惠券查询可能返回空数组，此时应如实提示"该门店当前无可用优惠券，按原价核算"，不得虚构优惠。

## 6. 实测示例

以下两组案例均在门店「麦当劳广州萝岗敏捷广场餐厅」（storeCode: 1400492，到店自取）完成，数据取自真实接口返回。

### 6.1 成功配餐案例（营养 + 预算双约束，带忌口）

**输入**：热量 ≤600 kcal、蛋白质 ≥30 g、钠 ≤1800 mg、预算 ≤40 元、不吃牛肉。

**配餐推演**

| 步骤 | 加入商品 | 累计（热量/蛋白/钠） | 累计价 | 判定 |
|---|---|---|---|---|
| 主堡候选一 | 麦辣鸡腿汉堡（485/24/1208） | 485 / 24 / 1208 | ¥22.5 | 余 115 kcal，需再补 ≥6 g 蛋白 |
| 试加小食 | 薄皮焦香V翅（192） | 677 | — | 热量超限，回退 |
| 试加次优 | 4块麦乐鸡（170）→ 655 | — | — | 热量超限，回退 |
| 试加次优 | 纯牛奶（129）→ 614 | — | — | 热量超限，回退；苹果片蛋白为 0，蛋白不达标 |
| 主堡候选二 | 板烧鸡腿堡（391/23/1041） | 391 / 23 / 1041 | ¥23.5 | 余 209 kcal、余 ¥16.5 |
| 加入小食 | 薄皮焦香V翅（192/17/594） | 583 / 40 / 1635 | ¥39.0 | 四项约束全部通过 |
| 试加第三件 | 苹果片 / 纯悦 | — | ¥46.0+ | 超出预算，不予加入 |

**输出**

```
板烧鸡腿堡（1406）  ｜¥23.50｜391 kcal｜蛋白质 23 g｜钠 1041 mg
薄皮焦香V翅（520445）｜¥15.50｜192 kcal｜蛋白质 17 g｜钠 594 mg

【整单合计】热量 583 kcal（上限 600，余 17）｜蛋白质 40 g（目标 30，超额 +10）｜钠 1635 mg（上限 1800，余 165）
【总价】¥39.00（预算 ¥40，剩余 ¥1.00；优惠 −¥0.00 —— 该门店当前无可用优惠券，按原价核算）
【取餐建议】堂食（eat-in）/ 外带店内自提（take-in-store）
```

**接口校验**：价格试算返回 `originalPrice: 3900`、`price: 3900`、`discount: 0`（单位分），换算为 ¥39.00；优惠券查询返回 `data: []`。钠占上限 90.8%，已按规则提示当日其余餐饮保持清淡。

### 6.2 边界无解案例（触发降级逻辑）

**输入**：热量 ≤500 kcal、蛋白质 ≥30 g、钠 ≤1500 mg、预算 ≤30 元、不吃牛肉。

**推演结论**：门店中非牛肉且规格明确的主堡最高蛋白为板烧鸡腿堡 23 g、麦辣鸡腿汉堡 24 g，任一主堡叠加 4 块麦乐鸡均达到 561 kcal 与 ¥35，热量与预算同时破线；仅靠小食组合最高为薄皮焦香V翅 + 4 块麦乐鸡的 27 g 蛋白。**500 kcal 与 30 g 蛋白在该门店条件下互斥，判定无解。**

**剔除说明**：薯条、麦乐鸡、鲜萃咖啡、麦辣鸡翅因规格不明未参与搭配。

**最接近方案**

```
薄皮焦香V翅（520445）｜¥15.50｜192 kcal｜蛋白质 17 g｜钠 594 mg
4块麦乐鸡（521143）  ｜¥11.50｜170 kcal｜蛋白质 10 g｜钠 337 mg

【整单合计】热量 362 kcal（达标）｜蛋白质 27 g（目标 30，差 3 g）｜钠 931 mg（达标）
【总价】¥27.00（预算 ¥30，剩余 ¥3.00；优惠 −¥0.00）
【取餐建议】堂食 / 外带
```

接口返回 `price: 2700`（单位分），即 ¥27.00，`discount: 0`。

**放宽建议一（放宽热量与预算）**

板烧鸡腿堡 + 4块麦乐鸡 → 561 kcal / 蛋白质 33 g / 钠 1378 mg / **¥35.00**（接口返回 `price: 3500`）。条件为热量上限放宽至 570 kcal（+70）、预算放宽至 ¥35（+5），其余约束全部达标。

**放宽建议二（下调蛋白质目标）**

蛋白质目标下调至 27 g，其余不变 → 采用上方最接近方案：362 kcal / 27 g / 931 mg / ¥27.00，全部指标达标，且较预算节省 ¥3。

## 7. 限制与免责

1. **数据源依赖**：全部营养与价格数据来自麦当劳 MCP 接口，接口返回的准确性、时效性与完整性由数据提供方负责；如营养表中缺少某商品记录，该商品将被剔除而不会估算补全。
2. **营养数据口径**：营养表为通用数据，不区分门店；营养值对应标准份，实际出品可能存在个体差异。
3. **菜单时效性**：菜单与编码随时间变化，本技能虽要求每次重新拉取，仍不能保证与实际点餐瞬间的上架状态完全一致。
4. **非医疗建议**：输出结果为基于公开营养数据的配餐参考，不构成医疗、营养治疗或减肥方案建议。孕期、哺乳期、糖尿病、肾病等特殊人群及患有基础疾病者，应遵医嘱安排饮食。
5. **过敏风险**：本技能不做过敏原筛查，食物过敏人群请以麦当劳官方过敏原信息为准。
6. **不做交易**：本技能不涉及订单创建、支付、配送与优惠券核销，任何交易行为均不在其能力范围内。
7. **价格仅供参考**：价格试算结果为即时测算值，最终以门店实际结算金额为准。
